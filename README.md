# TRW Studio

Текущий выпуск: **Patch07, исправлен после браузерной проверки**, доработки по двум видео и боты для Telegram/MAX.
Отчёт и ограничения: `docs/PATCH_07_RU.md`. Браузерная проверка выполнена; аппаратная Android-приёмка открыта.

Astro + Tailwind CSS, статический сайт для GitHub Pages с доменом `trwstudio.art`.

## Локальная работа

Node.js 24 (также используется в GitHub Actions), npm.

```bash
npm ci
npm run check
npm run build
python3 scripts/verify_build.py
npm run preview -- --host 0.0.0.0
```

Для разработки: `npm run dev -- --host 0.0.0.0`.
Архив содержит исходники; `node_modules`, `.git` и локальные инструменты не включаются.
Готовая статическая сборка лежит в `dist/`. Исходники изменяют в `src/`, затем пересобирают.

## Предпросмотр в SPCK Editor на Android

Распакуйте полный ZIP и откройте `index.html` в корне папки `TRW_Studio`.
Он открывает готовую сборку `dist/index.html`. Устанавливать Node.js или собирать Astro
в SPCK для просмотра не нужно. Не открывайте `.astro` как HTML.

В основном выпуске уже исправлены относительные пути к CSS, JS, изображениям и страницам.
Та же папка `dist/` работает на домене, при размещении во вложенном каталоге и через file://.
Отдельного SPCK-архива нет. `npm run build` автоматически сохраняет эту переносимость.

## Настройки

`site.config.mjs` — домен, название, цвет, публичные контакты и внешние ссылки проектов.
При смене домена нужно также обновить `public/CNAME` и настройки GitHub Pages.
Секреты и токены в публичный проект не добавляются.
Форма сохраняет согласованный переход через Telegram Share и ручную отправку в приложении.

Согласованные решения и следующие этапы: `docs/ROADMAP_RU.md`.
Что изменено и проверено: `docs/PATCH_01_RU.md`, `docs/PATCH_02_RU.md`, `docs/PATCH_03_RU.md`, `docs/PATCH_04_RU.md` `docs/PATCH_05_RU.md` `docs/PATCH_06_RU.md` и `docs/PATCH_07_RU.md`.

## Публикация

Workflow `.github/workflows/deploy.yml` проверяет и собирает исходники при push в `main`,
затем публикует сайт в GitHub Pages. Скачивание или распаковка ZIP ничего не публикует.
Изменения следует сначала просмотреть локально; публикацию выполняет владелец репозитория.
